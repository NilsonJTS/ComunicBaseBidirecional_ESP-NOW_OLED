29/07/26 e 30/07/26: Criação do banco de dados no hostgator (codigo sql em docs), criação de arquivo php para recepção dos dados e inserção no banco (codigo php em docs), vinculo de esp32 com site para envio de dados em formato json. Este vinculo foi o maior desafio até o momento, consumiu aproximadamente 15 horas de trabalho e pesquisa, e depois de tudo, através do chatgpt, descobri que eu não estava usando a abordagem mais comum para o objetivo, eu estava usando uma função para enviar os dados e isso é o padrão, no entanto eu estava chamando a função logo ao final da função de callback, que recebe os dados do emissor a cada 1seg, e desta forma eu parava toda a execução do callback que esperava o fim da execução da função de envio de dados para o hostgator, e isso causou o mal funcionamento de tudo que estava operante até o momento, afinal o emissor continuava mandando o sinal com os dados, mas o receptor estava aguardando a execução de outra tarefa, além da falha de conexão com o hostgator. A solução veio com a abordagem padrão event flag (eventos+flag), então tenho uma var global bool para economizar dados e manter eficiencia de execução criada como false, ao passar por todo o processo de callback ela recebe true, e DENTO DO LOOP há uma verificação if(flag){ flag=false; enviarDadosHostgator();} desta forma a flag volta a esperar nova alteração dentro do callback, pois recebeu false novamente, e executa o envio de dados.
